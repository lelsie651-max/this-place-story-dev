# 设计系统基础目录

本目录只存放设计系统和未来独立编辑器可读取的数据，不参与当前小程序运行时逻辑。

## 当前文件职责

- `design-tokens.json`
  记录当前真实颜色、字号、字体、间距、圆角、阴影和基础组件样式。
- `component-registry.json`
  记录主要可视化组件的稳定 `designId`、来源文件、选择器和可编辑属性。
- `asset-manifest.json`
  记录当前背景、Banner、占位图、字体、tabBar 图标策略和资源替换约束。

## 当前实现边界

- 已做：
  - 为主要页面组件补充稳定 `data-design-id`
  - 把现有 WXSS / app.json 中的真实设计值整理成结构化数据
  - 把当前资源使用方式整理成清单
- 未做：
  - 未让小程序运行时读取这些 JSON
  - 未生成新的 WXSS
  - 未实现拖拽编辑器
  - 未修改任何业务逻辑、跳转、云函数或数据查询

## 是否适合新增 `design-editor/`

适合。

推荐后续在仓库根目录新增独立网页工具：

```text
design-editor/
```

原因：

1. 当前页面结构已经比较稳定，主要问题是样式值和组件标识分散在 WXML/WXSS。
2. 本目录已经提供了编辑器最需要的三类输入：
   - Token
   - 组件注册表
   - 资源清单
3. 独立网页工具可以和小程序业务代码解耦，避免把编辑器逻辑塞进小程序工程。

## 编辑器能力评估

当前工程适合分层支持以下能力：

- 可以支持：
  - 拖拽组件
  - 调整宽度
  - 调整高度
  - 修改颜色
  - 修改字体
  - 修改文字
  - 替换背景图片
  - 替换 Banner 图片
  - 修改圆角
  - 修改阴影
  - 显示/隐藏组件
  - 保存多个设计版本
  - 撤销和重做
  - 预览不同屏幕尺寸
- 需要保守处理：
  - 修改位置
    当前很多页面依赖 flow/flex 布局，适合改 `margin/padding/alignment`，不适合默认改成绝对坐标。
  - 拖拽组件
    第一版更适合“区块排序 + 对齐/间距调整”，不建议直接允许任意自由定位。

## 适合由编辑器控制的内容

- 标题
- 按钮
- 卡片
- Banner
- 图片
- 颜色
- 字体
- 间距
- 圆角
- 阴影

这些内容大多只影响视觉层，和当前业务逻辑解耦程度较高。

## 不应由编辑器直接控制的内容

- 云函数
- 数据查询
- 投稿提交
- 审核状态
- 放大镜扣减
- 足迹记录
- 页面跳转
- 用户权限
- 动态列表逻辑

这些内容属于行为层或权限层，必须继续由业务代码和后端控制。

## 推荐技术方案

推荐采用“三者结合，但以 JSON 配置为主”的方案：

1. 编辑器优先修改 JSON 配置
   - 修改 `design-tokens.json`
   - 修改页面布局配置
   - 修改资源清单中的替换目标
2. 小程序侧后续新增一层“设计配置应用器”
   - 可以在构建阶段生成 WXSS
   - 也可以在受控范围内让页面读取一小部分 JSON 配置
3. 对稳定公共样式，优先生成 WXSS
   - 例如颜色、字号、圆角、按钮高度、卡片内边距
4. 对页面级开关和资源替换，优先走 JSON
   - 例如某区块是否显示、Banner 使用哪张图、某段标题文案是什么

推荐理由：

- 直接让编辑器改源码 WXSS，回滚、审查和版本管理都比较重。
- 只靠 JSON，又不足以覆盖所有现有样式规则。
- 先用 JSON 管“设计意图”，再由工具生成或同步 WXSS，最适合当前项目的渐进式改造。

## 推荐实施顺序

1. 先把当前 token 真正接入公共 WXSS
2. 再补页面级布局配置文件
3. 再创建 `design-editor/` 只读预览版
4. 最后再做可编辑、可保存、可导出的正式版本

## 第一版编辑器建议

第一版建议只支持：

- 页面切换预览
- 组件选中高亮
- 修改标题/按钮/卡片的颜色、字体、圆角、阴影、间距
- 替换推荐卡片封面和背景
- 显示/隐藏非业务型组件
- 保存设计版本
- 撤销/重做
- iPhone / Android 常见宽度预览

先不要支持：

- 任意自由拖拽到绝对坐标
- 改动动态列表结构
- 改动按钮事件和页面跳转
- 改动云函数和数据字段

## 当前约束说明

- `data-design-id` 是本轮选用的稳定标识方案，因为它不会影响现有布局和事件。
- 当前 tabBar 为微信原生 tabBar，颜色可以被设计系统管理，但精确高度仍要通过运行时测量补足。
- 当前项目没有本地图片目录，也没有自定义字体文件；未来替换资源前要先确定包体、兼容性和裁切规则。
