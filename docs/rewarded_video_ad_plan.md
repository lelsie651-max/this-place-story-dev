# 激励视频广告放大镜奖励方案

## 1. 目标

在不改变现有放大镜使用规则的前提下，引入微信激励视频广告。

用户完整观看一次激励视频后，可额外获得 `1` 枚放大镜。

## 2. 不可改变的现有规则

以下规则继续保持不变：

- 用户每天成功使用放大镜总次数最多 `10` 次
- 同一用户、同一天、同一地点、同一故事标签最多 `3` 次
- 民间传说命中预设也消耗放大镜
- AI 失败、超时、非法 JSON 不消耗放大镜

广告奖励与上述规则的关系：

- 广告奖励只增加余额
- 广告奖励不增加当天已成功使用次数
- 广告奖励不重置每日 `10` 次限制
- 广告奖励不重置同地点同标签 `3` 次限制
- 广告奖励不修改 AI 请求统计与 DeepSeek 费用统计

## 3. 前端接入规则

当前前端使用微信原生接口：

```js
wx.createRewardedVideoAd({
  adUnitId: '<真实 adUnitId>'
})
```

当前接入约束：

- 仅在 `wx.createRewardedVideoAd` 可用且配置了真实 `adUnitId` 时创建广告对象
- `adUnitId` 为空、仍为占位符或云函数不可用时，不显示广告奖励入口
- 广告只由用户主动点击按钮后播放
- 不自动弹出广告

当前按钮文案：

- 正常状态：`看视频获得 1 枚放大镜`
- 达到每日广告奖励上限：`今日广告奖励已用完`

当前成功与失败提示：

- 成功：`已获得 1 枚放大镜`
- 中途退出：`完整看完视频后才能获得放大镜`
- 加载或播放失败：`广告暂时不可用，请稍后再试`

## 4. 完整观看判定

当前最小可行判定：

- 监听激励视频关闭回调
- 只有 `close` 回调明确表示完整观看结束时，才向服务端申请奖励
- 中途关闭、加载失败、播放失败都不申请奖励
- 每次播放生成唯一 `rewardRequestId`
- 前端保留页面级请求锁，避免快速重复点击

## 5. 服务端发奖方案

当前使用云函数：

- `claimAdReward`

客户端仅提交：

```json
{
  "action": "claim",
  "rewardRequestId": "唯一请求 ID",
  "adUnitId": "真实广告位 ID"
}
```

服务端固定处理：

- 通过 `wx.cloud.getWXContext().OPENID` 获取当前用户身份
- 固定发放 `+1` 枚放大镜
- 不接受客户端传入 `userId`
- 不接受客户端传入 `openid`
- 不接受客户端传入 `rewardCount`
- 不接受客户端传入 `magnifyingGlass`

## 6. 数据记录

当前使用集合：

- `ad_reward_claims`
- `ad_reward_daily`
- `users`

`ad_reward_claims` 至少记录：

```json
{
  "rewardRequestId": "唯一请求 ID",
  "userId": "服务端 OPENID",
  "adUnitId": "广告位 ID",
  "reward": 1,
  "date": "YYYY-MM-DD",
  "createdAt": "服务端时间"
}
```

`ad_reward_daily` 至少记录：

```json
{
  "date": "YYYY-MM-DD",
  "userId": "服务端 OPENID",
  "rewardCount": 1,
  "updatedAt": "服务端时间"
}
```

当前服务端使用事务保证：

- 同一 `rewardRequestId` 不重复领取
- 每个用户每天最多通过广告获得 `3` 枚放大镜
- 发奖与记录保持一致
- 云函数失败时不增加放大镜

## 7. 幂等与可信边界

当前实现的可信边界必须明确：

- 当前是“客户端完整播放回调 + 服务端幂等发奖”的最小方案
- 服务端能保证同一个 `rewardRequestId` 不会重复加余额
- 服务端能保证每日第 `4` 次广告奖励被拦截
- 当前版本不能宣称已经实现微信广告平台服务端验真

## 8. 配置边界

- `adUnitId` 不属于 API Key
- `adUnitId` 可以保存在前端配置中
- DeepSeek API Key 仍然只能保留在云函数环境变量中
- 未配置真实 `adUnitId` 时，广告奖励入口必须隐藏

## 9. 部署与验收重点

部署前需要确认：

- `claimAdReward` 云函数已部署
- `ad_reward_claims` 集合可正常写入
- `ad_reward_daily` 集合可正常写入
- `users` 集合可正常更新 `magnifyingGlass`

真机验收至少覆盖：

1. `adUnitId` 正确时按钮显示
2. `adUnitId` 为空或占位符时按钮隐藏
3. 完整播放后增加 `1` 枚放大镜
4. 中途退出不增加放大镜
5. 广告加载失败不增加放大镜
6. 同一个 `rewardRequestId` 重复提交不会重复领奖
7. 每日第 `4` 次广告奖励被拦截
8. 广告奖励不改变当天已使用次数
9. 广告奖励不绕过地点和标签限制
